# 城乡基建

《城乡基建》是一款 2~4 人回合制基建竞争游戏。玩家在随机生成的 6x6 居民点地图上修建道路和桥梁，引导商人沿最短路径完成交易并收取过路费。项目包含可直接游玩的本地模式和基于 Node.js 服务器的线上房间模式。

## 功能概览

- 2~4 名玩家的本地轮流游玩。
- 自动生成合法的 6x6 城乡地图，城市与乡村由河流分隔。
- 每个骰子点数 1~6 恰好对应 6 个居民点。
- 开局预建设、两枚骰子、道路、桥梁、商人和过路费系统。
- 四种建设卡和对子抽卡机制。
- 卡牌图鉴、规则介绍、实时游戏日志。
- 线上创建房间、房间列表、加入、观战、准备、开始、聊天、房主踢人和断线重连。
- 线上模式使用服务器权威校验行动，不信任客户端自己传入的随机状态。
- 使用 SSE 实时推送房间快照，并以 HTTP 轮询作为降级方案。

## 游戏规则

### 游戏目标

地图中会先后出现 4 位小商人和 1 位大商人。玩家修建自己的道路、桥梁，让商人通行并收取过路费。第 5 位商人完成交易后游戏结束，过路费总额最高的玩家获胜；如果过路费相同，则比较已建设道路数。

### 地图与开局

- 地图是 6x6 居民点，坐标显示为 `(x, y)`，`(1,1)` 是城市方向，`(6,6)` 是乡村方向。
- 每局随机生成一条不经过居民点的河流，将城市和乡村分成两个单连通区域。
- 地图中的 36 个居民点会被均匀分配数字 1~6，每个数字出现 6 次。
- 每名玩家开局按顺序选择并建设一条合法道路。

### 回合流程

正式回合中，当前玩家先排出第一骰。根据第一骰可以三选一：

1. **抽建设卡**：立即抽取并执行一张卡。
2. **基地修路**：选择一个点数等于第一骰的居民点作临时施工基地，再从与基地相邻的合法边中选一条修建道路。
3. **基地掷第二骰**：选择基地后掷出第二骰。如果基地旁有对应点数的相邻居民点，可在两点之间修路或修桥。如果两枚骰点相同，额外抽取一张建设卡并立即执行。

一个回合结束后，服务器或本地引擎会检查当前商人是否已经可通行。若可通行，商人沿最短路径结算过路费，并开始下一位商人。

### 道路与桥梁

- 相邻居民点之间有一条边。边上可分别保存道路所有者和桥梁所有者。
- 非跨河边可直接建路。
- 跨河边必须先由自己建桥，再在桥上建路。桥梁不能替代道路通行，只有同时存在桥和道路时商人才能通过。
- 不能在他人桥梁基础上建路，也不能使用他人的桥。

### 商人与过路费

- 前 4 位小商人的起点、终点会在城市和乡村之间随机生成。
- 第 5 位大商人固定从 `(6,6)` 前往 `(1,1)`。
- 商人只能沿已建道路通行，并在所有最短可通路径中等概率选取一条。
- 小商人沿道路每单位长度支付 1$，沿桥梁每单位长度额外支付 4$。大商人的所有过路费为小商人的 2 倍。

## 建设卡图鉴

| 卡牌 | 概率 | 效果 |
| --- | --- | --- |
| 随机修路卡 | 2/5 | 系统随机选择一条满足条件的可建道路，如果没有合法边则本次无效。 |
| 桥梁通路卡 | 1/5 | 选择自己已建桥但尚未建路的跨河边，补建道路。 |
| 拆路修桥卡 | 1/5 | 先拆除自己的一条道路，再在任意无桥跨河边上建桥。 |
| 资金补贴卡 | 1/5 | 立即获得 **2$** 过路费，无需选择目标。 |

卡牌图鉴在游戏首页和游戏中均可打开。

## 模式

### 本地模式

本地模式不需要服务器，所有玩家共用一个浏览器页面轮流操作。选择玩家数量和名称后，点击“开始本地新游戏”即可开局。

### 线上模式

线上模式由 Node.js 服务器保存房间和游戏状态，每个客户端使用一个房间 ID 和会话 token 身份。

1. 在创建方填写房间名、玩家名和人数，点击“创建线上房间”。
2. 其他玩家可在房间列表点击“加入”，也可使用房间 ID 和记忆中的 token 重新连接。
3. 房主创建后可看到每个座位。房间坐满后，非房主玩家需要逐一点击“准备”。
4. 所有座位坐满且准备完成后，房主点击“开始游戏”。
5. 房主可在等待阶段踢出其他玩家，离开后房主可自动转移。
6. 游戏中支持聊天、观战和断线重连。

服务器通过 SSE 推送房间状态。如果 SSE 不可用，前端会自动使用轮询请求保持同步。断线后只要 localStorage 中的会话信息仍在，重新打开同一个地址即可尝试恢复。

## 启动

要求 Node.js 18 或更新版本。在项目根目录执行：

```powershell
npm test
npm run serve
```

然后在浏览器打开：

```text
http://127.0.0.1:5173
```

服务器默认监听 5173 端口。也可通过 `PORT` 环境变量改端口：

```powershell
$env:PORT=8080
npm run serve
```

直接双击 `index.html` 可以查看本地 UI，但如需使用线上模式，必须通过 `npm run serve` 访问。

## API

所有房间 API 返回 JSON，线上游戏的动作由 `/api/rooms/:roomId/actions` 统一接受。

```text
GET  /api/rooms
POST /api/rooms
GET  /api/rooms/:roomId?clientToken=...
GET  /api/rooms/:roomId/events?clientToken=...
POST /api/rooms/:roomId/join
POST /api/rooms/:roomId/leave
POST /api/rooms/:roomId/ready
POST /api/rooms/:roomId/kick
POST /api/rooms/:roomId/chat
POST /api/rooms/:roomId/start
POST /api/rooms/:roomId/actions
```

`/api/rooms/:roomId/actions` 支持以下 action 名称：

- `preBuildRoad`：开局预建设。
- `startTurn`：开始当前玩家回合并排出第一骰。
- `buildFromBase`：选择第一骰基地并修路。
- `rollSecondDieForBase`：选择基地并排出第二骰。
- `resolveSecondDieBuild`：解决第二骰对应的建设。
- `drawCard` / `resolveCard`：抽取和解决建设卡。
- `skipBuildRoad` / `skipAction` / `finishTurn`：无合法操作时跳过并推进回合。

## 最短路径算法

商人寻路使用 BFS 构建最短路径 DAG，再用动态规划统计每个后继节点的路径数。从起点出发时按剩余路径数加权选择，使每条完整最短路径被等概率选中。实现位于 `src/game.js` 的 `GameEngine.findUniformRandomShortestPath(startNodeId, endNodeId)`。

## 开发提示

- 线上随机数和游戏状态只在服务器内部保存，快照中不包含 `randomSeed` 和 `randomState`。
- 房间使用内存存储，服务器重启后房间会清空。
- 请在开发和测试时使用 `npm test` 确认核心规则和线上 API 均保持正常。
